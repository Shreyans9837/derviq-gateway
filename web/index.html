03 / Complete tutorial

How Derviq works, step by step.

Intent → Identity → Authority → Risk → Policy → Approval → Execution → Evidence → Recovery.

01

Agent creates an intent

The model decides it wants to call a tool, write data, change a record or trigger a workflow.

02

Derviq identifies the actor

The request is associated with an explicit machine identity instead of treating every request as anonymous application traffic.

03

Delegation is checked

The system can represent which principal granted the agent its authority and inspect its permitted scope.

04

Context enters the decision

Agent, target, action, amount, risk context and other request attributes can affect the decision.

05

Policy decides

The request can be allowed, denied, degraded or escalated before the side effect.

06

Human approval can be an exception path

Higher-risk actions can require explicit approval while routine actions remain automated.

07

Execution crosses a controlled boundary

Only the permitted action reaches the registered execution or upstream integration.

08

Evidence is committed

The current engine creates SHA-256 hash-linked evidence records that can be verified for continuity.

09

Recovery is explicit

Supported workflows can issue compensating actions. Universal rollback is not assumed because external systems differ.

09 / Security honesty

Do not call a prototype magic.

Derviq is designed around explicit boundaries and testable behavior. The website deliberately distinguishes current implementation from future infrastructure.

CURRENT ENGINE

What exists in the production-oriented core

PostgreSQL persistence, tenant-scoped API-key authentication, agent lifecycle controls, policy evaluation, evidence hashing, verification, rate limiting, request limits and controlled HTTP execution/recovery paths.

NOT AUTOMATICALLY SOLVED

What requires real infrastructure

Universal rollback, cloud KMS/WORM guarantees, eBPF enforcement, real financial settlement, enterprise certification and independent security testing require dedicated infrastructure, integrations and verification.

16 / FAQ

Clear answers. No magic.

Is Derviq an AI model?

No. Derviq is positioned as a control layer intended to sit across models, clouds and agent frameworks.

Does the current demo move real money?

No. The current demo does not claim real financial settlement.

Is SHA-256 a zero-knowledge proof?

No. The current evidence mechanism is a tamper-evident SHA-256 hash chain, not a zero-knowledge proof system.

Can Derviq universally roll back anything?

No. Recovery depends on the external system and requires workflow-specific compensation or native transaction support.

Is the current engine enterprise-certified?

No certification claim is made here. Enterprise deployment requires independent security review, threat modeling, operational hardening and relevant compliance work.

What does cross-vendor mean?

The architecture is intended not to depend on a single model provider, cloud provider or agent framework.
